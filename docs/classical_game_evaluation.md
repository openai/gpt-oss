# 以製作遊戲檢查古典學者

本次題目為「九宮移數」，要求模型交付一個可獨立開啟的 HTML 遊戲。
這是測試用題名，不宣稱此遊戲在古代已有同名記載。

## 目前狀態

工作環境未找到模型權重、Ollama 程式、GPU 工具或模型服務憑證。
現有網頁為介面預覽，回報 `model_ready: false`，不能產生真實模型回覆。
因此尚無可供判定的模型遊戲、文風分數或修補前後比較。
不能將人工寫的遊戲或固定示範回答冒充此模型的實測成果。

## 執行

先啟動已載入真實模型的 BooleLOT Responses API，使用古典設定與札記索引。
在專案根目錄執行：

```bash
python -m gpt_oss.evals.classical_game_eval \
  --endpoint http://127.0.0.1:8000/v1/responses \
  --model gpt-oss-20b --repair
```

若模型服務要求憑證，透過環境變數 `CLASSICAL_EVAL_API_KEY` 注入，不寫入紀錄。
遠端服務須支援 Responses API，並已套用專案的古典角色；單純指定模型名稱不會使一般服務自動載入角色。
結果位於 `data/classical/game-eval/`，包含實際提示、原始 JSON、原文、抽出的遊戲與報告。
有明顯疑點時，`--repair` 會將疑點連同前稿交回同一個模型，最多改寫一次。
疑點關鍵字僅為覆核線索，不能證明文言合格、不合格或遊戲已可玩。

## 人工驗收

1. 文風：說明、註釋與畫面是否為清楚自然的繁體文言；必要語法與介面名稱可保留。
2. 知識：是否以古代觀念立論、是否捏造古籍出處、是否把程式技藝特例擴張成後世世事知識。
3. 成品：在隔離瀏覽器開啟抽出的遊戲，確認無載入錯誤、無外部依賴。
4. 操作：開局未完成且可解；只允許相鄰移動；無效移動不計步；完成時顯示勝局；重局可恢復。
5. 可靠性：反覆開局、觸控與窄螢幕使用；檢查洗牌是否從已解局作合法移動，而非直接任意排列。

先記下實際失敗，再修改提示、札記或實作。修補後以相同題目再驗，保留兩版輸出。
若只有題材知識不足，補入有來源的古典札記；若為程式錯誤，補具體失敗步驟；
若為文風問題，提供相同意思的文言改寫範例。未實際驗證的項目保持未驗。
